## 1. What this is, in one paragraph

OpenClaw runs on the Mac as a local "AI employer": a **manager** AI plans work and hands tasks to **worker** AIs, reviews what comes back, and reports. It runs on the owner's two subscriptions — **ChatGPT Plus** (GPT-6 Astra, via the Codex harness) and **Claude Pro** (Claude models, by driving the Claude Code CLI already installed) — with **no API keys and no pay-per-use billing**. Its first job is auditing the chapter அ Meta integration against the offline Meta docs. It is **read-only**: it never pushes, deploys, touches the live database, or edits the owner's real project folder.

**Status: built, fenced, fence-tested, and end-to-end tested — the full manager → researcher → co-manager chain ran green on 2026-09-20 (§9 to-do 1).** Not yet moved to a server, and **on hold there by the owner's decision** (§9 to-do 5).

**The structure was checked against published 2026 evidence on 2026-09-21. Verdict: sound, with one role on watch.**
- **Do NOT downgrade the manager to Sonnet.** The clearest finding in the literature: *"You cannot cheap out on the orchestrator while using cheaper models for workers — it's a false economy"*; delegation *"works reliably only on the two strongest models"* because *"the orchestrator capability has a floor."* **Strong orchestrator + cheap workers is the winning pattern** — one benchmark kept **96% of an all-frontier team's score at 46% of the cost**. Astra stays. (The owner asked about this twice; the manager is on `thinkingDefault: medium`, never high — that worry was unfounded.)
- **The verifier is the best-founded role.** Guidance says a judge should be *"at least as strong as the generator, from a different family if possible"*, and **Opus 4.7 is specifically named as one of 2026's two default frontier judges**. Cheap-reader + strong-judge tiering is documented to cut cost **59.4% for identical verified results**. Do not touch it.
- **The co-manager was TRIMMED to plan-review only (owner's decision, 2026-09-21), not removed.** The asymmetry is the point: **a wrong plan is the one mistake nothing downstream can repair**, because the verifier only checks claims that *were* made, never the ones nobody thought to look for — so a badly-framed plan silently spends a whole job's budget on the wrong question, and no later check can catch it. Verdicts are the opposite: **the verifier already re-checks every finding from a different AI company**, so a second opinion there was duplicated work, and the first real job showed it (agreement on all ten verdicts — the textbook *diversity-collapse* signal). Recommended fixes reach the owner regardless; he is the second opinion. Net effect: the co-manager costs roughly **one turn per job** instead of several, Opus 5 largely leaves the scarce Claude pool, and the team is close to 2 GPT / 2 Claude — which also eases the rate-limit concentration that bit twice on 2026-09-20. **AGENTS.md still requires the manager to record AGREED/DISAGREED in the report; keep tracking that ratio.** If the co-manager never disagrees on plans across three jobs either, removing it entirely becomes defensible.
- **⚠ Original note (the research behind that decision):** Findings on debate are mixed (*"a well-prompted single model does about as well"*; *"debate and base-model quality may be substitutes"*), and there is a named failure mode, **"debate diversity collapse": when disagreement trends to zero, the vote no longer carries information.** **In the one real job so far it agreed on all ten verdicts** — exactly that signal, from one sample. The counter-argument is real (cross-family checks catch errors same-family ones miss). **Record agree/disagree per decision point; if it never disagrees across three jobs, it is a paid rubber stamp.**
- **Two researchers, not more, and on DIFFERENT families.** *"Multiple competent but individually limited agents can outperform a single stronger agent when they draw on diverse models"* — but *"adding more agents yields little when systems are homogeneous, as correlated outputs produce diminishing returns."* A second Luna would buy almost nothing; Sonnet 5 buys real diversity.
  **⚠ CORRECTION — a second researcher is NOT failover, and an earlier note here wrongly implied it was.** The **manager runs on ChatGPT too**, from the same allowance as Researcher A. If ChatGPT is exhausted the manager stops, and **a stopped manager cannot delegate anything to Researcher B** — it simply idles. That is precisely what happened on 2026-09-20: ChatGPT ran dry and the researcher *and* the Telegram bot both went down, because both depend on Astra. **The manager is the single point of failure and a second researcher does not change that.** What actually recovers from an exhausted limit is the **resume gate** (§7a). The two genuine benefits of Researcher B are (1) diversity of error modes, and (2) **ChatGPT burns roughly half as fast**, because the manager no longer pays for all the reading — so the limit arrives later, or not at all. ## 7. Usage limits and resuming

- The two plans run out **independently**. Claude out → researcher/verifier/co-manager stop. ChatGPT out → the manager stops, so the whole job stops. **No cross-fallback is configured on purpose** (keeps spending predictable and the roles honest).
- OpenClaw retries briefly, then stops the step with the reset time, e.g. `You've reached your Codex subscription usage limit. Next reset in 7 minutes, Sep 20 at 4:15 AM`. Auth profiles go into a short cooldown. Nothing strange happens; the heartbeat lane fails cleanly.
- **There is no built-in auto-resume** — OpenClaw lists `usage_limited` as "reserved for a future usage-limit stop state". So the **heartbeat** does it: the manager runs a cheap turn whose prompt (`agents.defaults.heartbeat.prompt`) says: read the newest `*-progress.md`; if a job is unfinished and was stopped by a limit, refresh the copy and continue; if the limit is still in force or nothing is pending, reply "nothing to do"; never start new work.
- **Observed 2026-09-20:** a burst of setup tests exhausted the **5-hour** ChatGPT window while the **weekly** stayed at **84% left**. The 5-hour window is the binding constraint — pace bursts, and check `openclaw models status` first.
- **⚠ THE HEARTBEAT WAS QUIETLY EATING THE ChatGPT BUDGET — retuned 2026-09-20 (owner spotted it).** It ran **every 30 min on `gpt-6-astra`**, the flagship, to perform a trivial "is anything pending?" file check. The owner measured **~4–6% of the 5-hour window per run**: 10 runs per 5-hour window ⇒ **40–60% of the entire ChatGPT allowance consumed doing nothing**, on idle days. Fixed with three knobs (all hot-reload, no restart):
  - `agents.defaults.heartbeat.model` → **`openai/gpt-5.6-luna`** (the cheap tier; the heartbeat never needed a flagship)
  - `agents.defaults.heartbeat.every` → **`2h`** (was the built-in default ~30 min ⇒ 4× fewer runs; still far finer than the 5-hour limit it exists to wait out)
  - `agents.defaults.heartbeat.lightContext` → **`true`** (boolean, needs `--strict-json`)
  - **Other knobs available if it is still too expensive:** `activeHours` (skip quiet hours — but this also disables overnight resume, which is when it is most useful), `isolatedSession`, `timeoutSeconds`.
  - **The prompt was ALSO rewritten as a cheap fast path + expensive slow path (owner's idea, 2026-09-20).** The original prompt told the heartbeat to consider resuming and to follow AGENTS.md *before* it knew whether anything was pending, so it loaded context and deliberated on every check — including the ~95% that end in "nothing to do". It now reads **one** file (the newest `-progress.md`), and if nothing is outstanding replies `nothing to do` and **STOPs** — explicitly forbidden from opening AGENTS.md, planning or explaining. Only genuinely unfinished work triggers the full resume path.
  - **Why the heartbeat still runs as `main` rather than a cheap dedicated agent.** The owner correctly observed that detecting "is the goal finished?" needs almost no intelligence, and that the manager could work out *what* remains by itself — a detector/doer split. That design is right, but the **mechanism is undocumented**: `heartbeat.target`, `.session` and `.to` all have empty schema descriptions, and `main` is **not** in `agents.defaults.subagents.allowAgents`, so a cheap agent cannot simply spawn the manager. The resume path is what rescues interrupted overnight jobs, so it was not rebuilt on a guess. **If a day of measurement shows the heartbeat is still expensive, build the dedicated agent then — and test that it can actually wake `main` before trusting it.**
  - **⚠ THE REAL CAUSE WAS `isolatedSession`, AND IT WAS UNSET. Fixed 2026-09-20.** OpenClaw's own docs: *"`isolatedSession: true` … avoids sending full conversation history (~100K tokens down to ~2–5K per run)."* Without it the heartbeat runs **inside the manager's main session and re-sends the entire history every time** — which is exactly why a one-file check cost 4–6% of the 5-hour window. This is a known, widely-reported bug: **GitHub issue #20011, "built-in heartbeat only runs in main session — causes inevitable context bloat with no escape hatch"**; community reports describe ~120K tokens per trivial check, ≈$0.75 a run, and one user burning **$18.75 in a single night** on ~25 idle checks, with session files reaching 10–15 MB. **Set `isolatedSession: true` on any new install before anything else.**
  - **It also fixes a risk introduced by changing the heartbeat model.** The docs warn of **context bleed**: a heartbeat on a smaller model "can leave it active for the next main-session turn, potentially causing overflow." Isolation is the documented remedy, so the Luna switch is only safe *with* `isolatedSession: true`.
  - **Final heartbeat config: `model openai/gpt-5.6-luna · every 2h · lightContext true · isolatedSession true` + a fast-path prompt.**
  - **Deliberately NOT applied, with reasons — do not "optimise" these later without re-reading this:**
    - **`bootstrapMaxChars` 20000 → 10000** (the most-repeated community tip) **WOULD BREAK THIS INSTALL.** `AGENTS.md` is **12,093 chars** and the chapter அ section is at its **end**, so halving the cap silently truncates the team table, spawn models, golden rules and worker boilerplate. Total bootstrap is 24,578 chars against a 60,000 cap, so nothing is truncated today. **Re-measure before touching either number.**
    - **`activeHours`** (e.g. 09:00–19:00) saves idle-hours cost but **disables overnight resume**, which is the heartbeat's entire purpose.
    - **`target: "none"`** runs for internal state only and **does not deliver**, so the owner would stop being told when a job finishes or needs his decision.
    - **`HEARTBEAT.md` is obsolete** — migrated to monitor scratch via `openclaw doctor --fix`; `lightContext` does not need it. Don't create one.
  - **Still available if it is ever needed:** `/compact` or `/clear` on a bloated session (community reports ~47% cost cut), `contextPruning` in cache-ttl mode, `agents.entries.*.params.cacheRetention`, and `/context list` for a per-file token breakdown. The main session sat at **40k/258k tokens with a ~7 MB store** on 2026-09-20 — worth compacting before a big job, but harmless.
  - **Do NOT "fix" this by moving the heartbeat onto a Claude model.** Claude Pro is the *scarcer* pool — it is shared by the researcher, verifier, co-manager **and the owner's own Claude Code sessions**. Moving the drain there makes things worse, not better.
  - **Unverified:** whether `gpt-5.6-luna` draws from the *same* 5-hour pool as `gpt-6-astra` or a separate one. `openclaw models status` reports a single pooled `openai usage` figure, so a cheaper model probably weighs less against the same pool rather than escaping it. Confirm by watching the drop per heartbeat over a day rather than assuming.

## 7c. First real automatic resume — successful gate, incomplete checkpoint (diagnosed 2026-09-22)

This incident is the first real proof of the expensive half of the resume system. It proves the gate can wake Astra, resume after a provider reset, run a Claude worker, save new work, and announce the result. It also exposes a separate design defect: **a checkpoint that records only progress is not necessarily sufficient to reconstruct the original authorized job.**

### What happened, in order

1. The broad `marketing-full` audit was authorized with checkpoint version 2. Claude/Anthropic became limited, so the job saved progress as `waiting_for_limit`, `blockedProvider: anthropic`, with exact `notBefore: 2026-09-21T15:20:00Z`.
2. After that time the five-minute gate evaluated the state as `limit-window-reached` and fired. Scheduler evidence at diagnosis: `lastFiredFingerprint: "marketing-full|2|waiting_for_limit|2026-09-21T15:20:00Z"`; last run status `ok`; delivery `delivered`; no consecutive scheduler errors.

6. Rather than invent exclusions, the manager correctly failed closed: it wrote the progress report, set `status: waiting_for_user`, cleared `blockedProvider` and `notBefore`, sent the Telegram message, and stopped. No finding was finalized and no project file was changed.
7. The gate kept ticking normally afterward. It saw fingerprint `marketing-full|2|waiting_for_user|` and returned `lastDecision: waiting_for_user`, exactly as its contract requires. A later provider reset cannot change that state and the gate does not probe provider availability on idle ticks.

The original task explicitly pointed to `META-AUDIT-CONTEXT.md` and said §4 owns M1–M13. Both copies still exist and are identical:

- Real project: `/Users/krutesh/Downloads/Website Flow Multi-Pickup/META-AUDIT-CONTEXT.md`

The progress checkpoint recorded that M1–M13 were required but did not record their source path, contents, or the full original request. Consequently, the new manager lacked the pointer that the original session had. Memory failure exposed that omission, but memory failure did not create it.

## 8. Traps already hit — do not repeat these

1. **Never restart the gateway / install plugins / change config while the Mac app's onboarding is open.** Doing so broke the app's sign-in step ("The Gateway did not complete activation… retry the saved sign-in"; log: `config reload failed: The plugin or restart requirement changed before activation`). Fix was to quit the app, let it settle, and clear the stale `openclaw.onboardingSystemAgentPending` defaults key; the relaunch then logged `openclaw.setup.verify ✓`.
2. **Redaction: BSD `sed` has no `\s`.** A redaction regex silently failed and printed the gateway auth token into the chat transcript. Mask with `sed -E 's/[A-Fa-f0-9]{32,}/<hidden>/g'` (and for base64-ish, `[A-Za-z0-9_+/=-]{40,}`). If a token does leak: `openclaw config set gateway.auth.token "$(openssl rand -hex 24)"` then `openclaw gateway restart` (done once already; fingerprint ecb26dd5 → 6c6b1682).
3. **`openclaw agents delete <id>` moves that agent's WORKSPACE to the Trash.** The retired `worker` agent's workspace was the owner's real project folder. Safe procedure: first `openclaw config set agents.entries.<id>.workspace <an empty dir>`, then `openclaw agents delete <id> --force --json`, then confirm the project file count and `git rev-parse --short HEAD` are unchanged (they were: 6748 files, caa2689). **This near-miss is why OpenClaw now works on a copy.**
4. **Sub-agent model precedence.** A cross-agent spawn used `agents.defaults.subagents.model` and ignored the target agent's own `model`, so the "Opus verifier" silently ran on Sonnet (the manager itself reported the mismatch). Fix: set per-agent `agents.entries.<id>.subagents.model` **and** tell the manager in `AGENTS.md` to pass `model` explicitly. **Always verify from the log line** `cli turn: provider=claude-cli model=…` — never from the config alone.
5. **claude-cli native tools are all-or-nothing.** In this OpenClaw version `resolveCliNativeToolApprovalPlan` returns *allow* only for `security=full, ask=off`, *deny* for `security=deny`, and otherwise **prompt** — for every native tool including **Read**. Unattended, that means denied. Native **Bash** is the exception: under `ask: on-miss` it is checked against the exec allowlist. **Consequence: give Claude agents read access through allowlisted look-only binaries (`cat`, `head`, `grep`…), never by loosening exec.**
6. **Never set a claude-cli agent to exec `full`.** Tried once for the read-only worker: per-agent `tools.deny` did **not** restrict Claude's native tools, and the worker then ran shell, wrote `/tmp`, and fetched the web. Reverted within a minute; nothing harmful ran. The audit's own advice for read-only agents is deny `exec`+`process`, or a real sandbox.
7. **The exec allowlist approves whole programs, not arguments** (arg-level pinning is an exact-argv hash). That is why helper wrappers exist instead of allowlisting `git`.
8. **`openclaw agent -m "…"` returns EMPTY output when the manager hands off and yields.** That is not a failure. Read `openclaw sessions list` and `openclaw logs --limit N`.
9. **Config types are strict:** `env.vars.X` must be a **string** (`'"false"' --strict-json`), booleans/numbers need `--strict-json`, and object merges need `--merge`.
10. **Batch config changes.** After 3 CLI restarts in 10 minutes the gateway warns about a "restart storm".
11. **`openclaw sessions delete` needs `--yes`**; `openclaw config unset` refuses to drop an agent entry (use `agents delete`, with trap 3's precautions).
12. **zsh:** `$var:word` triggers history modifiers — always write `${var}` in loops (this mangled a session key mid-test).
13. **ChatGPT models need the official `clawhub:@openclaw/codex` plugin.** Without it the app says "No agent model is configured" even though the sign-in worked. Install official-publisher plugins only.
14. **Don't use models you can't vouch for.** `claude-cli/claude-fable-5-1`, `claude-fable-5`, `claude-mythos-5`, `openai/gpt-5.6-sol|terra|luna` are in the catalog but were deliberately not used.
15. **Read access is path-unrestricted on the Mac.** `cat` is allowlisted, so an agent can read any file the user can (including `~/.openclaw/openclaw.json`). They cannot write or send anything, and the copy protects the real project, but only a VPS or a Docker sandbox gives true isolation.
16. **Never ask an agent "what folder are you in?" — `pwd` is not allowlisted, so the question cannot be answered.** This stalled to-do 1's own test on 2026-09-20: the researcher asked to run `pwd`, sat as a pending approval for ~3 minutes, and under `askFallback: deny` an unattended run would simply have lost that time. **Prove location by property, not by path string:** `ls -a` (allowlisted) shows the copy has **no `.git`** while the real project does, which proves both *where the agent is* and *that it cannot reach git* — strictly more than `pwd` would have proven. A denied approval costs real time but is not fatal: the researcher recovered by itself, though the turn took **185s instead of ~29s**.
17. **`openclaw logs --max-bytes` caps at 1000000, and going over returns NOTHING, not an error.** `--max-bytes 2000000` fails server-side as `INVALID_REQUEST` while the shell pipeline still exits 0, so a `grep` over it prints zero lines and looks exactly like "no matching events". Same silent-pass trap as `CLAUDE.md`'s SQL-assertion rule. Keep `--max-bytes` ≤ 900000, and if a log query returns nothing unexpectedly, re-run it without the grep before believing the silence.
18. **Long worker replies reach the manager TRUNCATED, and the manager cannot tell what it lost.** On the first real job (2026-09-20) **all four** researcher returns plus the co-manager's decision-point-1 answer came back cut off; the manager flagged each one and refused to treat unread text as reviewed, which is the right behaviour but means evidence is silently dropped. There is no retention/truncation key in `openclaw.json` to raise — it is internal. **Mitigation: cap what workers return, not what they read.** Tell every worker task to reply with at most N findings, each at most ~3 lines, in a fixed shape (claim · doc file + quote · `file:line` · one-line reasoning), and to write nothing else. A worker that answers in long prose will lose its best evidence off the end. Treat a manager note of "truncated" as a reason to re-ask narrowly, never as a reason to drop the area.
