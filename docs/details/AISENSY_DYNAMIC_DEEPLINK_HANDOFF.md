# AiSensy Dynamic Deeplink CTA Handoff

## Purpose

This doc records the exact working format for sending AiSensy WhatsApp campaign
messages with a dynamic URL CTA button.

We spent time testing several plausible payload shapes. The key learning is:
**do not guess the button payload shape from Meta examples or carousel examples.**
For AiSensy campaign sends, use the JSON body generated by AiSensy's own
"View JSON body" option for the specific campaign.

## Working Campaign

The working tested campaign was:

```text
car_abandon_deeplink2
```

The template body:

```text
Hi {{1}}, we don't want you to miss our {{2}} - {{3}}.

If you need any help, kindly press Contact Us.
```

Template parameter mapping:

```text
{{1}} = user name
{{2}} = event name
{{3}} = event date
```

The CTA button URL in the WhatsApp template is configured like:

```text
https://chaptera.in/invite/{{1}}
```

The button's `{{1}}` is separate from the message body's `{{1}}`.

## Exact Working Payload Shape

This is the working shape for a normal non-carousel campaign with one dynamic
URL CTA button:

```json
{
  "apiKey": "YOUR_AISENSY_API_KEY",
  "campaignName": "car_abandon_deeplink2",
  "destination": "918838111564",
  "userName": "Krutesh",
  "templateParams": [
    "Krutesh",
    "Chill Sunday Meetup",
    "Sunday, July 19th"
  ],
  "source": "manual-test-view-json-body-shape",
  "media": {},
  "buttons": [
    {
      "type": "button",
      "sub_type": "URL",
      "index": 0,
      "parameters": [
        {
          "type": "text",
          "text": "?phone=8838111564&name=Krutesh"
        }
      ]
    }
  ],
  "carouselCards": [],
  "location": {},
  "attributes": {
    "variant": "view_json_body_shape"
  },
  "paramsFallbackValue": {
    "FirstName": "Krutesh"
  }
}
```

The successful live test returned:

```text
submitted_message_id: a87c9aa3-72ba-459d-b83d-6fd171947622
```

The resulting CTA deeplink worked correctly.

## Critical Button Formatting Details

The button object must match AiSensy's generated JSON body exactly:

```json
{
  "type": "button",
  "sub_type": "URL",
  "index": 0,
  "parameters": [
    {
      "type": "text",
      "text": "?phone=8838111564&name=Krutesh"
    }
  ]
}
```

Important details:

```text
type     = "button"  lowercase
sub_type = "URL"     uppercase
index    = 0         number, not string
text     = dynamic replacement for the button URL's {{1}}
```

This combination matters. Similar-looking variants were either ignored or
rejected.

## How The Final URL Is Built

If the approved WhatsApp button URL is:

```text
https://chaptera.in/invite/{{1}}
```

and the API sends:

```json
"text": "?phone=8838111564&name=Krutesh"
```

the final CTA URL becomes:

```text
https://chaptera.in/invite/?phone=8838111564&name=Krutesh
```

WhatsApp/Meta may append click-tracking params such as `fbclid`, `_wapm`, or
`_waaem`. That is normal. What matters is that our dynamic value appears before
those tracking params.

## How To Get The Correct Payload For A New Campaign

For every new AiSensy campaign with a dynamic CTA:

1. Create the WhatsApp template in AiSensy.
2. Add a CTA button.
3. Choose URL as the button type.
4. Configure the URL with a dynamic variable, for example:

```text
https://chaptera.in/invite/{{1}}
```

5. Submit the template for WhatsApp approval.
6. Once approved, activate the campaign.
7. Open the campaign in AiSensy.
8. Click the three-dot menu in the top-right.
9. Choose the option to view the JSON body.
10. Copy the generated JSON body.
11. Replace only the placeholder button parameter value in that generated body.

Do not infer the casing, index type, or field names from a different AiSensy
sample. AiSensy's generated JSON body is the source of truth.

## Failed Formats We Tested

### 1. Adding the button value as a 4th body template param

Payload idea:

```json
"templateParams": [
  "krutesh",
  "event",
  "date",
  "?phone=8838111564&name=Krutesh"
]
```

Result:

```text
Template params does not match the campaign
```

Reason:

The message body has only 3 variables. The button variable is separate and
does not count as body `templateParams[3]`.

### 2. Meta-style uppercase button object

Payload idea:

```json
"buttons": [
  {
    "type": "BUTTON",
    "sub_type": "URL",
    "index": 0,
    "parameters": [
      {
        "type": "text",
        "text": "?phone=8838111564&name=Krutesh"
      }
    ]
  }
]
```

Result:

AiSensy accepted/submitted the API call, but the CTA did not receive the dynamic
value. The delivered URL stayed at the base URL with Meta tracking params.

Reason:

This shape resembles carousel/Meta examples, but it was not the generated JSON
shape for the normal campaign.

### 3. Lowercase `sub_type: "url"` with string index

Payload idea:

```json
"buttons": [
  {
    "type": "button",
    "sub_type": "url",
    "index": "0",
    "parameters": [
      {
        "type": "text",
        "text": "offer"
      }
    ]
  }
]
```

Result:

AiSensy/Meta reported:

```text
parameter is invalid
```

Reason:

For the working campaign, AiSensy's generated JSON body used uppercase
`"URL"` and numeric `0`.

### 4. `buttonValue0`

AiSensy support mentioned `buttonValue0` as a possible field.

Payload idea:

```json
"buttonValue0": "?phone=8838111564&name=Krutesh"
```

Result:

The API accepted the message, but the CTA link did not include the dynamic
value. The delivered link stayed like:

```text
https://chaptera.in/invite?fbclid=...
```

Reason:

For this campaign, the generated JSON body did not use `buttonValue0`; it used
the `buttons` array shown above.

## Recommended Code Helper Shape

If this is wired into an Edge Function, build the button array like this:

```ts
function capitalizeFirstChar(value: string): string {
  const trimmed = (value || '').trim();
  if (!trimmed) return 'User';
  return trimmed.charAt(0).toUpperCase() + trimmed.slice(1);
}

function buildAiSensyUrlButton(value: string) {
  return [
    {
      type: 'button',
      sub_type: 'URL',
      index: 0,
      parameters: [
        {
          type: 'text',
          text: value,
        },
      ],
    },
  ];
}
```

Example usage:

```ts
const userName = capitalizeFirstChar(name);
const buttonValue = `?phone=${phone}&name=${encodeURIComponent(userName)}`;

const payload = {
  apiKey: AISENSY_API_KEY,
  campaignName: 'car_abandon_deeplink2',
  destination: `91${phone}`,
  userName,
  templateParams: [
    userName,
    eventName,
    eventDate,
  ],
  source: 'cart-abandonment',
  media: {},
  buttons: buildAiSensyUrlButton(buttonValue),
  carouselCards: [],
  location: {},
  attributes: {
    event_slug: eventSlug,
  },
  paramsFallbackValue: {
    FirstName: userName,
  },
};
```

## Operational Notes

- `destination` should include country code, e.g. `918838111564`.
- Store the AiSensy key in environment secrets, not frontend code.
- Do not trust `{"success":"true"}` alone. AiSensy may accept a request while
  the delivered WhatsApp CTA still ignores the dynamic value.
- Verify success by opening the CTA in the delivered WhatsApp message.
- Meta/WhatsApp click tracking params are normal. Check whether our dynamic
  value appears before those params.
- If a new template or campaign is created, repeat the "View JSON body" step
  and follow that exact generated button shape.
